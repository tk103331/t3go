# 多环境、局域网直连与云端中继

状态：第一版已实现（2026-11-15）。先阅读以下使用说明和实现边界；
后半部分保留完整设计目标，其中标明的设备授权、云端账户等仍属于后续工作。
原有单地址直连与配对方式继续兼容，见 [README](../README.md)。

## 当前可用功能

- SQLite 中保存 Ed25519 环境身份。`environmentId` 是公钥的 base64url 表示，
  服务重启与地址变更不改变身份；`Server.ID` 仍表示一次启动实例。
- 客户端保存多个环境，支持打开、别名、默认环境、忘记连接及路线偏好。
  草稿、附件草稿、排队消息、选中线程、固定线程、模型缓存按环境隔离。
- 切换环境保存当前输入并取消原页面的订阅与请求，旧回调不会写入新页面。
  远端任务继续执行。重新打开环境后，排队消息需要手动恢复。
- 配对链接可包含直连和中继地址及固定身份。每条候选路线先验证随机挑战签名，
  再发送 Token；直连优先，失败时尝试中继。模式为 Auto、Direct、Relay。
- 事件流故障可触发换路线；失败路线冷却 30 秒。使用中继至少 45 秒后，
  每 30 秒检查直连，连续两次成功才恢复直连。Relay 模式不探测直连。
  尚未接入平台网络状态或前后台监听。
- HTTP、附件流、SSE 与终端 WebSocket 通过同一隧道转发。隧道断开后退避重连，
  中继撤销登记会关闭现有隧道及其活动流。
- SSE 游标超出保留窗口、超过数据库当前序号或直播序号断档时重新获取快照。
  等待响应头最长 8 秒，55 秒无数据或心跳则断开重连；安静的流建立后也会清除离线状态。
  401/403 暂停自动恢复与待发送队列，不继续切路线尝试授权。
- 主聊天发送前持久化 Request ID，服务端将 run、消息、线程状态和回执原子提交。
  同线程同键同内容返回原 run，同键不同内容或附件返回 409。回执随线程保留，
  删除运行记录也不会使该请求再次执行；环境重启后返回 run 的实际恢复状态。
  未确认消息保持暂停，可显式查询回执或用原请求重试，不自动重放业务写入或终端输入。
  未声明 `idempotentMessages` 的旧服务端沿用手动检查流程。

## 配置与使用

先在公网主机上运行中继。该服务也可以提供自己的执行环境与 Web 客户端：

```sh
t3go serve --home /srv/t3go --listen 0.0.0.0:4870 --relay --web web
```

在前面配置可信 HTTPS 反向代理，并允许 WebSocket Upgrade 和 SSE 长连接，
关闭 SSE 缓冲。`--relay` 必须启用鉴权。中继管理员 Token 是该数据目录
已有的 `token` 文件；通过可信方式取得，仅在登记或撤销时使用。

在电脑上登记本地环境（这里的 `--home` 是电脑自己的数据目录）：

```sh
t3go relay --home /path/to/local-data \
  --server https://relay.example.com \
  --admin-token-file /path/to/hub-admin-token \
  --direct-url http://192.168.1.20:4870

t3go serve --home /path/to/local-data --listen 0.0.0.0:4870 --connect-relay
t3go pair --home /path/to/local-data --relay
```

`--direct-url` 可省略，此时只走中继，电脑服务可继续只监听 loopback。
要从局域网访问，则明确监听局域网地址或 `0.0.0.0`，并允许对应防火墙端口；
无需为出站中继连接配置路由器入站端口映射。每台电脑使用独立数据目录登记。

手机或桌面客户端打开侧栏底部的网络图标，在 Environments 中选择
Add environment，把上述配对链接粘贴到连接页的地址或 Token 栏。
同一环境的已验证路线会合并。Open 切换环境，Rename 仅改客户端别名，
Default 记录默认环境（启动时优先恢复上次活动环境），Forget 删除本机保存的
连接凭证，保留本机草稿和远端项目。正在运行的任务不因切换而停止。

仅在明确可信的测试网络中，可用 `http://...` 并在登记命令中添加
`--allow-http`。签名探测只验证描述内容，不能保护未加密的后续 Token 和业务流量，
也不能防止主动网络攻击者转发探测；公网应使用可信 HTTPS。
Web 端受浏览器混合内容、CORS 和局域网访问权限约束，HTTPS 页面未必能直连
HTTP 局域网地址；不可达时使用中继，Direct 模式不回退。

撤销某个环境的中继登记：

```sh
t3go relay --home /path/to/local-data \
  --server https://relay.example.com \
  --admin-token-file /path/to/hub-admin-token \
  --revoke ENVIRONMENT_ID
```

成功撤销后，若本机 `relay.json` 与该中继和环境匹配，也移除该凭证文件。
然后可重新登记。撤销只影响中继入口，局域网直连权限由电脑的 Token 决定。

## 第一版存储与接口

| 位置 | 内容 |
| --- | --- |
| 环境 SQLite `environment_identity` | 单例 ID 与 Ed25519 私钥 |
| 环境 SQLite `message_receipts` | 线程内 Request ID、请求摘要、原 run ID 和接收时间 |
| 电脑 `relay.json`（0600） | 中继地址、环境 ID、连接凭证和可选直连地址 |
| 中继 `relay-bindings.json`（0600） | 环境公钥、名称、地址及连接/访问 Token 的 SHA-256 摘要 |
| 客户端 `environments:v1` | 版本、环境配置、活动/默认环境、路线及共享 Token |
| 客户端 `env:<id>:<key>` | 每个环境的草稿、队列和 UI 状态 |

| 接口 | 权限与用途 |
| --- | --- |
| `GET /api/v1/environment?challenge=...` | 公开的随机挑战签名描述 |
| `POST /api/v1/relay/environments` | 中继管理员登记环境，返回独立连接凭证 |
| `GET /api/v1/relay/environments` | 中继管理员列出登记与隧道在线状态 |
| `DELETE /api/v1/relay/environments/{id}` | 中继管理员撤销并关闭活动隧道 |
| `GET /relay/connect/{id}` | 电脑连接凭证建立 WebSocket + yamux 隧道 |
| `/e/{id}/{path...}` | 环境 Token 鉴权后代理到电脑原有接口 |
| `POST /api/v1/threads/{id}/messages` | 环境 Token；可选 `requestId` 对同线程消息去重 |
| `GET /api/v1/threads/{id}/receipts/{requestId}` | 环境 Token；查询接收回执，不触发执行 |

电脑连接器只连接当前环境固定的本地 TCP 端口。中继不能通过请求参数指定
任意内网主机。每个环境有独立隧道与 HTTP 连接池；重复登记或重复活动隧道
均拒绝，避免悄悄替换已有连接。中继状态当前是单进程，不支持多副本。

## 尚未实现的设计目标

当前仍使用原有的**共享环境 Token**，作为本地 API 与该环境中继入口的访问凭证，
本地 API 仍会再次检查它。电脑连接凭证独立生成，仅允许建立对应隧道。
尚无云端账户、一次性设备配对、独立中继访问会话或单客户端设备撤销；
配对链接授予完整环境权限，应该按密码管理。Token 变更后需撤销并重新登记。

客户端凭证目前保存在 NSGo Storage 中，没有接入系统安全存储；
现有终端/资源 URL 的 `?token=` 兼容方式仍保留，短期票据尚未统一。
第一版信任中继运营者读取业务内容，未提供端到端加密。
没有 mDNS、自动发现网卡、自签证书固定、跨中继优先级、数据库恢复代次、
创建线程等其他写操作的幂等保证或多环境后台实时订阅。复制整个环境数据库会复制身份，
当前没有“作为新环境导入”的重置命令。

消息回执表示已接收，不保证外部工具副作用“恰好一次”。查询返回 404 时，原 POST
仍可能稍后提交，应保留原 Request ID；支持该能力时才允许原请求重试。
目前去重作用域为环境数据库中的线程与 Request ID，没有独立设备授权作用域。
数据库恢复到接收前的旧快照可能丢失回执，数据代次检查仍待实现。

下面各节是完整设计蓝图。与上面的“当前可用功能”不同的能力，均为后续目标，
不能据此认为当前版本已具备设备级授权、证书固定或完整的安全凭证流程。

## 目标和边界

一个客户端管理多个执行环境；每个环境有多条访问路线。手机与桌面端共用环境
管理和选路逻辑，Web 端根据浏览器实际能力选择可用路线。

- 环境管理自己的项目、线程、文件、Git、终端、Provider、执行权限和数据库。
- 同一台电脑可以用不同的数据目录运行多个环境。
- 客户端选择环境，连接管理器选择路线。换路线不等于换环境。
- 云端同时可以提供一个执行环境和中继服务，两种角色分开授权。
- 已配对的局域网环境可以脱离云端使用，不强制注册中继。
- 第一版信任中继服务器处理业务内容，不承诺对中继运营方的端到端加密。
- 不同步不同环境的文件或数据库，不把云端目录映射成电脑本地目录。

## 身份与数据归属

### 环境、中继和路线

| 对象 | 身份与归属 | 内容 |
| --- | --- | --- |
| Environment | 稳定 `environmentId`，绑定环境公钥 | 环境名称、身份版本、执行能力 |
| Instance | 每次服务启动的新 `instanceId` | 识别重启和运行时连接失效 |
| Hub | 独立 `hubId` 和服务身份 | 中继地址、所属管理主体、登录状态 |
| HubBinding | `(hubId, environmentId)` | 云端登记、路由授权、连接凭证和撤销状态 |
| Route | 归属于一个环境 | 直连或中继地址、来源、健康状态、最近成功时间 |
| ClientDevice | 客户端设备公钥或设备 ID | 电脑本地授予的访问权限 |
| EnvironmentSession | 客户端本地对象 | 环境快照、事件游标、路线、连接和缓存 |

环境 ID 与密钥保存在环境数据目录，启动时只读或首次生成，禁止随 IP、
名称和路由改变。首次创建要保证原子写入；环境注册完成前不得发布身份。

支持同一环境绑定多个中继；多个入口只有在环境身份一致时才能合并。名称相同、
目录相同、同一 IP 或同一主机名都不足以判断是同一环境。

复制完整数据目录会复制身份，必须提供“作为新环境导入”流程，重置身份并使
旧绑定失效。检测到同一身份的并发连接不能无条件踢掉已有会话；需要结合绑定、
连接代次和实例信息判断冲突，并给出可见错误。

客户端记录和远端执行数据分开：

- 本地记录可以包含用户自定别名、顺序、默认环境、路线偏好和凭证引用。
- 环境描述、权限、项目和线程由对应环境确认；本地别名不改远端名称。
- 中继登记中的“在线”只表示隧道已连接，不能代替本地服务健康检查。

### 客户端存储

采用带版本的环境注册表，例如 `environments:v1`、`activeEnvironmentId`；
可变环境数据使用 `env:<environmentId>:<key>` 命名空间。

| 层级 | 数据 |
| --- | --- |
| 全局客户端 | 主题、字号、客户端布局偏好、环境顺序、默认环境 |
| 每个环境 | 当前项目/线程、草稿、附件草稿、固定线程、项目折叠、模型缓存、事件游标 |
| 每个环境的运行时 | 请求取消句柄、搜索计时器、终端连接、会话代次、发送状态 |
| 中继连接 | 中继凭证引用、已登记环境、最近同步时间 |
| 远端环境 | Provider 配置、默认模型、执行权限、项目、线程、运行和审批 |

`threadId`、附件 ID、审批 ID 和终端 ID 均与 `environmentId` 一起引用，
不依赖它们在不同数据库间碰巧不重复。全局搜索结果也必须包含环境归属。

凭证通过独立的 CredentialStore 访问，环境注册表只存引用。原生目标应使用
平台安全存储；Web 的凭证存储和同源会话单独适配，不假定 Go 与 WebView 共用
同一凭证仓库。现有环境设置中的 Theme/Accent 需要客户端覆盖优先级：
已明确设置的客户端偏好优先，其次环境默认值，最后系统值。

## 加入环境和授权

### 三种加入方式

1. 通过可信的配对链接或二维码直接加入环境，可以不依赖中继。
2. 登录某个中继，查看获准访问的环境，再由环境确认客户端设备授权。
3. 手动输入地址或局域网发现，作为待验证候选，经过身份确认后加入。

发现结果与电脑上报的 IP 都不可信；在验证证书或完成基于已绑定环境公钥的
身份校验之前，不向候选地址发送长期凭证。初次加入必须通过二维码、可信渠道
或明确的指纹确认建立信任，不能仅接受候选地址自报的 ID。

一次性配对凭证只用于交换设备授权，有过期时间和消费记录；环境本地完成
消费与授权落库后才签发设备会话。中继不代替环境授予本地执行权限。

### 凭证分工

| 凭证 | 使用位置 | 范围 |
| --- | --- | --- |
| 管理凭证 | 创建绑定、管理中继或环境 | 管理操作，不用于常规终端链接 |
| 一次性绑定/配对凭证 | 新电脑绑定或新客户端加入 | 短时、一次性、明确绑定目标 |
| 电脑连接凭证 | 电脑向某个中继建立隧道 | 仅对应 HubBinding，不允许访问其他环境 |
| 中继访问会话 | 客户端请求指定环境的云端入口 | 限定管理主体、环境和有效期 |
| 环境设备会话 | 客户端访问本地环境 API | 由环境验证，可单设备撤销，直连与中继通用 |
| Socket/资源票据 | 浏览器终端、图片和附件入口 | 短时、限定环境、用途和资源 |

中继访问权限与环境 API 权限分别校验。拟议的原生 HTTP 转发使用独立的
中继授权头，例如 `X-T3Go-Relay-Authorization`；`Authorization` 留给环境
设备会话。中继验证后移除自己的凭证头，不覆盖环境凭证。

WebSocket 和无法添加授权头的资源请求使用先经鉴权签发的短期票据；票据
限定路径与用途，Socket 票据一次性消费，资源票据按资源读取语义设计。
中继入口的票据与环境票据分别管理，不能让一个票据获得任意目标的代理权限。

日志过滤凭证头与票据查询参数。新流程不把长期 Token 放进终端页面或资源 URL，
旧版 `?token=` 仅保留兼容；跨源重定向不得携带授权头。

解绑中继不自动删除本地客户端授权；若需要同时撤销，应明确提供该动作。
设备在电脑本地撤权后，两种路线都立即拒绝后续请求，并关闭该设备现存的
长连接。云端撤权只能保证云端路线失效；离线电脑无法即时获知云端撤权，
必须通过会话有效期和重新同步约束生效时间，界面不宣称即时撤销局域网权限。

## 局域网直连

服务端增加明确的直连监听和 TLS 配置；原有 loopback 用法保持兼容。启用
局域网监听不自动允许匿名访问，不自动修改路由器或系统防火墙。

直接路线来源包括手动配置、可信配对资料、中继同步的候选地址及可选的局域网
发现。服务端发布候选时只枚举合适的活动网卡，排除 loopback 和不可用地址；
VPN、多网卡和 IPv6 地址作为独立候选处理，客户端仍逐条验证。

已配对原生客户端可通过固定环境身份所绑定的证书访问局域网 TLS 服务。
证书更新需要由已信任身份证明连续性，身份密钥变更需要重新确认。平台不能
支持此策略时，使用可信证书或保留中继路线，不全局关闭证书校验。

Web 端不能假定支持原生证书固定，也不能假定 HTTPS 页面能访问任意局域网
地址。直连必须满足浏览器实际的证书、跨源和本地网络权限要求；不可用时显示
原因并使用中继。新授权接口使用明确的允许来源策略，不能直接沿用全开放 CORS。

## 反向隧道与云端转发

### 电脑连接器

连接器随本地服务运行，使用有身份验证的出站 WSS 连接接入中继。通道内部使用
独立数据流承载不同连接，避免一个 SSE 长连接占用全部请求处理能力；具体复用库
在实现阶段评估并固定版本，不自创聊天或终端业务协议。

每条数据流只允许进入本地配置好的 T3Go 入口，不接受云端指定任意 IP、
端口、文件路径或 URL。电脑绑定的中继有明确身份，禁止将凭证转发到其他主机。

断线重连采用退避与抖动，限制上限；有心跳、握手超时、并发流和缓冲区限制。
连接代次用于保证旧连接的清理回调不会删掉新连接。关闭服务时先停止接入，
取消流并释放本地连接，再结束隧道。

### 中继代理

中继将 `/e/{environmentId}/<path>` 映射到对应环境的原有 `<path>`，
独立的根路由仍指向云端自身的执行环境。

- 每个环境独立管理隧道会话和代理连接池，不能跨环境复用后端连接。
- 身份验证和环境授权在打开代理流之前执行；离线立即返回结构化错误。
- 支持 HTTP 流式上传下载、SSE 及时刷新和 WebSocket Upgrade。
- 不整包缓存文件或无限缓存消息；请求取消、超时和背压传递到隧道。
- 约束路径重写、查询参数、转发头、重定向及上游返回的绝对资源地址。
- 上游描述、附件、终端、图片与 `/ws` 也要保留所选环境前缀。
- 隧道断开时，使旧代次的池内连接失效；撤权时关闭对应授权的活动流。

第一阶段中继使用持久化登记和单进程在线会话表。部署多副本前需要单独设计
会话归属和跨实例路由，不能只把环境登记表放进共享数据库就认为支持多副本。

## 路线选择与会话恢复

EnvironmentManager 管理环境注册表；每个 EnvironmentSession 拥有自己的
RouteManager、API Client、快照、游标和取消范围。RouteManager 统一管理
API、事件流、附件和终端的路线选择，不只修改 UI 上显示的服务器地址。

### 选路策略

客户端提供 `auto`、`direct-only`、`relay-only` 三种模式。自动模式优先使用
已验证的直连，失败时中继兜底；存在多中继时使用最近成功和显式优先级排序。

首次连接可并行探测已知候选，给直连约 1 秒的优先窗口，并允许中继握手并行
进行；总时间预算和具体参数在真机测量后确定。仅做身份/健康检查可以并行，
任何业务写操作不做跨路线竞速。

使用中继时低频探测直连；连续成功并达到最短驻留时间后才恢复直连，失败路线
进入冷却，避免网络抖动时反复切换。切后台时减少探测，恢复前台或网络变更后
重新检查。Android、iOS 和 Web 的网络状态只作为提示，不作为可达性证明。

各路线记录 `unknown/probing/healthy/degraded/unreachable/blocked` 状态。
身份冲突立即隔离该路线，不向其重发凭证；明确的设备撤权停止所有路线尝试。
网络错误可降级到其他路线，业务 4xx、权限拒绝和执行失败不触发换路重试。
只有中继登录过期时，可保留仍有效的独立直连会话。

### 换环境

保存旧环境草稿和 UI 状态，取消旧页面请求及 UI 订阅，然后恢复目标环境状态。
每个异步请求捕获 `environmentId` 和视图代次：旧回调可以更新其所属环境缓存，
但不能修改新环境页面；计时器、附件清理和搜索回调遵守同样规则。

切换不是 `disconnect`。不删除旧环境凭证、不清空其草稿、不停止已经由服务端
执行的 run、不关闭远端终端进程。旧页面终端连接可以断开，返回后重新附着。
删除附件只能调用它所属环境的客户端。

第一版完整订阅活动环境，后台环境只维护受限的健康/状态更新；无法确认的任务
数显示“上次同步”，不能显示为实时。多环境实时审批提示另立阶段，在具备每环境
订阅与去重后启用，不后台自动批准任务。

### 换路线

同一环境的候选 Client 验证成功后再发布为活动路线。后续请求使用新路线，
已建立且健康的流可继续使用旧路线；撤权或身份异常时必须立即关闭旧流。
每个活动连接知道自己的路线和代次，不能依赖一个可随时改变的全局 BaseURL。

事件游标保存最后成功应用的事件序号；保留窗口不足、序号倒退或数据代次变化时，
重新取得快照与当前线程详情，再接收快照游标之后的事件。新增重放窗口元数据及
可识别的 `resync_required` 信号；不能只依赖当前 SSE 返回成功就判断没有漏事件。
恢复数据库或导入快照时需要更新数据代次，不把服务启动实例当成数据代次。

终端重连使用同一终端 ID，恢复已有输出而非新建 shell；第一版允许重新渲染服务端
快照，若要求无重复增量显示需增加终端输出游标。终端输入不自动重放。

WebView 自建的终端 Socket 不能继承 Go Client 的证书固定和额外授权头：
实现时必须使用适配后的票据与证书策略，或原生网络桥接。若采用桥接，必须限制
消息来源与操作；不能把长期 Token 暴露给任意内嵌网页。路由能力不足时整次
会话保持中继，不能显示“直连”却遗漏附件或终端不可用的问题。

## 写操作与待发送队列

连接失败不等于执行失败。现有 `sendPrompt` 在请求失败后重新入队的行为必须在
自动换路前改造，否则响应丢失可能导致重复 run。

| 操作 | 恢复规则 |
| --- | --- |
| 读取列表、状态、文件 | 验证同环境后可重试 |
| SSE | 从已应用游标恢复或重新取快照 |
| 发送消息、创建线程 | 同一 Request ID 查询结果或去重重试 |
| 文件上传 | 独立上传 ID/完成状态，失败时不自动重传已完成文件 |
| Git 提交/推送、回滚、合并 PR、审批 | 未明确实现恢复契约前，显示结果待确认并查询，不盲目重放 |
| 终端输入 | 不自动重发，提示用户确认 |

对允许重试的写操作引入 `Idempotency-Key`，作用域至少为环境、授权设备和
业务操作；记录请求摘要、状态与资源 ID。相同键不同摘要返回冲突，同键并发
只能创建一次业务实体。保留时间需覆盖客户端的恢复窗口，过期后不得假装仍可
安全重试。中继原样转发键，结果记录在执行环境。

SQLite 中的幂等记录与 run/线程创建原子提交；涉及启动进程等外部副作用时使用
可恢复的执行登记。创建了 run 但环境随后重启，应返回该 run 的实际恢复状态，
不能再次执行或声称外部操作恰好一次完成。

客户端区分 `draft/queued/submitting/accepted/unknown/failed`。未知结果先对账，
不当成未发送。队列归属于环境与线程，第一版持久化文本、附件引用和 Request ID，
不持久化授权 Token；附件过期或删除时需要用户处理。

切到其他环境暂停原环境未提交队列；返回后恢复可见状态。客户端重启后显示待处理
队列，不自动补发。后台自动执行队列属于另行授权的功能。

## 拟议接口与兼容

| 入口 | 职责 |
| --- | --- |
| `GET /api/v1/environment` | 获取环境身份、启动/数据代次、协议能力和挑战响应 |
| `POST /api/v1/pairing/exchange` | 在环境本地消费配对凭证，签发设备会话 |
| `GET /api/v1/relay/environments` | 中继按当前主体列出获准环境和隧道状态 |
| `POST /api/v1/relay/enrollments` | 管理员创建短时电脑绑定凭证 |
| `POST /api/v1/relay/enrollments/exchange` | 消费凭证，登记绑定和电脑连接身份 |
| `POST /api/v1/relay/route-tickets` | 为指定环境和用途签发短期云入口票据 |
| `GET /relay/connect` | 验证电脑连接身份并建立隧道 |
| `/e/{environmentId}/…` | 去除前缀，向对应执行环境代理 |

电脑绑定流程与客户端配对流程是两种契约，凭证不得混用。环境列出接口放在
`relay` 命名空间，避免与本地环境身份入口及现有模拟器 `/devices` 冲突。
同一中继初期可以只有一个管理主体，但数据和权限模型仍明确 owner/grant，
不能让持有任意设备连接凭证的人获取全部环境。

老客户端可继续调用 `/api/v1`、使用现有 Token 和配对链接。新客户端发现
`environmentIdentity`、`deviceSessions`、`eventResumeWindow`、
`idempotentWrites` 等能力后才启用相应功能。未声明能力的旧服务保持单地址
兼容，不自动合并、不开启写操作跨路线重试。

`State.ServerID` 保留原有语义，不直接悄悄替换；新字段与协议能力明确区分
稳定环境 ID、实例 ID 和数据代次。协议重大不兼容时协商失败并解释原因。

旧客户端存储迁移：

1. 读取旧地址、Token 及全局草稿等内容，先写入临时的 legacy 环境记录。
2. 有新身份契约的服务通过可信流程确认身份后，将记录绑定到稳定环境 ID；
   旧服务保留本地 legacy ID，不使用其临时 `serverId` 合并记录。
3. 版本化写入新注册表和环境数据，最后提交迁移标记；失败可重入。
4. 验证迁移完成前保留旧键，避免半次迁移丢失草稿。
5. 升级后的每个环境单独恢复当前线程、固定状态和附件归属，不自动复制凭证到
   新发现路线，也不自动覆盖已有同身份环境的草稿。

## UI 与操作语义

手机和桌面提供相同的环境选择入口，显示名称、活动状态、当前路线和最后同步
时间。离线仍能查看已明确标记的缓存；发送和审批需等待可验证的在线环境。
新建项目、目录浏览、安装 Provider 和终端动作始终标明实际执行环境。

管理项包括添加、配对、别名、排序、默认环境、路线偏好、凭证更新和连接诊断。
显示诊断原因：地址不可达、证书/身份不符、中继登录过期、设备撤权或协议不兼容。

| 操作 | 影响 |
| --- | --- |
| 切换环境 | 保存并恢复客户端状态，不停止远端任务 |
| 暂时断开 | 停止本客户端连接，保留配对和草稿 |
| 忘记环境 | 删除本客户端记录与凭证，明确提示未提交草稿/队列的处理 |
| 撤销客户端 | 环境拒绝该设备的两种路线并结束对应连接 |
| 解除中继绑定 | 删除该绑定并停止隧道，不删除环境项目 |
| 删除远端项目或数据 | 继续使用独立的远端删除操作，不附带在移除环境中 |

## 实施阶段与验收

### P1：多环境与稳定身份（基础功能已实现）

增加 `internal/environment` 的身份模型及 `internal/client` 的环境会话管理，
服务端提供持久身份，NSGo 客户端支持手动添加、切换、默认环境与版本化迁移。
暂时使用明确选择的单一直连路线，不宣称具备自动中继。

验收：两个测试环境故意使用相同线程 ID 仍不串数据；A 的迟到回调不能覆盖 B；
草稿/队列/附件和固定状态隔离；重启保留身份；旧存储迁移失败后可重入。

### P2：安全直连与多路线（身份探测与选路已实现，设备授权/TLS 固定待实现）

实现设备配对、可撤销授权、直连 TLS/身份校验和 RouteManager。局域网发现是
可选增强，手动配对必须可独立使用。先覆盖原生端，再按 Web 实际能力开放路线。

验收：云端不可用时已配对直连仍可用；IP 被另一台设备占用时不泄露凭证；
撤权后流与请求均终止；身份或协议错误不被当成普通断线隐藏。

### P3：反向隧道（基础转发已实现，统一票据待实现）

新增 `internal/relay`，实现绑定、隧道会话、按环境代理、票据、状态与连接清理，
通过 `cmd/t3go` 的显式配置接入启动生命周期。

验收：同一中继连接两台电脑，REST、SSE、附件与终端都正确隔离；大上传不阻塞
其他请求；伪造环境 ID 无法越权；隧道重连时旧清理不误删新会话；新会话不使用
旧连接池；无有效绑定的电脑不能覆盖已登记环境。

### P4：自动换路与写入恢复（消息回执、事件恢复与路线稳定策略已实现）

已支持消息 Request ID 去重、未知结果显式对账、原请求重试和事件缺口检测。
发送结果不明时暂停队列，绝不自动重发。已实现路线冷却、连续探测恢复直连、
终端重连；移动端前后台策略与其他业务写操作的恢复契约仍待实现。

验收：服务端收到发送后故意断开响应，换路线后仍只有一个 run；SSE 缺口触发
快照重载；直连/中继抖动不反复换路；终端不重复发送输入；客户端重启不自动补发。

### P5：后台状态与运营

完善多环境运行/审批汇总、诊断、授权管理、限流与部署说明。多副本中继、
局域网自动发现和对中继端到端加密分别评估，不阻塞前四阶段。

README 仅列出已经实现的具体能力；阶段内其余目标继续保留在待实现列表。
构建与部署分开验收，本地构建成功不代表已经更新线上服务或下载站点。
